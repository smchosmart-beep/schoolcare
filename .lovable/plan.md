# 방문기록 탭에서 이관 기록이 보이지 않는 문제

## 확인된 원인 (2가지)

1. **계정 불일치**: 이관된 NEIS 기록이 heero913@sen.go.kr(상명초, 10건)이 아니라 teacher@school.ac.kr 계정(14,792건)에 저장되어 있습니다. 보건일지가 보였던 것은 teacher 계정으로 로그인했기 때문이고, 상명초 계정에는 이관분이 없습니다.
2. **검색 방식 한계**: 방문기록 탭(`StudentRecords.tsx`)의 학생 검색은 브라우저 **학생 명단(localStorage)** 에서만 이름을 찾습니다. 명단에 없는 학생은 검색 자체가 안 됩니다. 이관 기록만 있고 명단 등록이 안 된 상태에서는 검색 불가입니다.

## 해결 계획

### 1. 이관 기록의 계정 이전 (데이터 수정)
- teacher@school.ac.kr에 들어간 NEIS 이관분(2026-03-04~08-31 구간의 teacher_visit/completed 배치)을 heero913@sen.go.kr로 옮깁니다.
- 방법: teacher 계정의 해당 구간 이관분을 조회해 동일 내용으로 상명초 계정에 INSERT 후, 원본 DELETE. 이름은 이미 암호화된 상태이므로 트리거 재암호화를 피하기 위해 암호문 그대로 복사합니다(트리거는 '-----BEGIN PGP MESSAGE-----' 접두를 건너뜀).
- 실행 전 건수·기간을 다시 확인하고, 이전 후 양쪽 계정 건수로 검증합니다.

### 2. 방문기록 검색을 실제 기록 기준으로 변경
- 조회 기간(기본 학년도 3/1~익년 2월 말)의 방문 기록을 먼저 불러와, 거기에 등장한 학생(학년·반·번호·이름)을 검색 대상으로 만듭니다.
- 명단 학생도 함께 포함해 기존 동작 유지. 두 목록은 `학년-반-번호-이름` 기준 중복 제거.
- 검색 결과 항목에 방문 횟수 표시. 학생 선택 시 이미 불러온 기록에서 필터링.
- 기간 변경 후 "조회" 시 기록과 검색 목록 함께 갱신.

## 기술 메모
- 수정 파일: `src/components/admin/StudentRecords.tsx` 한 곳 + 데이터 이전 SQL 1회
- 기존 `get_visits_decrypted` RPC 그대로 사용 (스키마·정책 변경 없음)
- 인쇄 기능과 요약 카드는 현재 동작 유지

# 방문 기록 학생 재배정 기능

## 목표

오주안 학생에게 잘못 연결된 19건처럼 여러 학생의 기록이 섞인 경우, 기록을 삭제하지 않고 각 행을 실제 학생에게 안전하게 옮길 수 있게 합니다.

## 구현 내용

1. **방문기록 표에 학생 변경 작업 추가**
   - 각 방문 기록 행에 `학생 변경` 버튼을 추가합니다.
   - 버튼을 누르면 해당 기록의 일시·증상·처치를 확인하면서 실제 학생을 선택할 수 있는 창을 엽니다.

2. **이름 검색 중심의 학생 선택 창**
   - 이 기기에 저장된 학생 명단에서 이름으로 검색합니다.
   - 동명이인을 구분할 수 있도록 학년·반·번호를 함께 표시합니다.
   - 현재 연결된 학생과 새 학생을 나란히 보여주고, 최종 확인 후 변경합니다.

3. **기록 보존 및 즉시 반영**
   - 선택한 학생의 학년·반·번호·이름만 해당 방문 기록에 반영합니다.
   - 날짜, 증상, 처치, 투약, 체온 등 방문 내용은 그대로 보존합니다.
   - 변경 성공 후 해당 기록은 오주안 목록에서 즉시 빠지고, 새 학생의 방문기록으로 조회됩니다.
   - 실패 시 기존 연결을 유지하고 오류를 안내합니다.

4. **검증**
   - 3월 26일 밴드 기록은 오주안에게 그대로 남깁니다.
   - 나머지 기록을 각각 재배정한 뒤 오주안의 총 방문 횟수가 1건으로 표시되는지 확인합니다.
   - 재배정된 기록이 실제 학생 검색 결과와 이전 방문 기록에 나타나는지 확인합니다.

## 기술 메모

- 수정 대상: `src/components/admin/StudentRecords.tsx`
- 학생 선택에는 기존 로컬 학생 명단(`loadStudents`)을 사용합니다.
- 기존 `visits` 행의 학생 식별 필드만 업데이트하며 데이터 삭제나 신규 테이블 생성은 없습니다.
- 이름 암호화는 기존 데이터베이스 업데이트 트리거가 그대로 처리합니다.
